# 거부 응답과 참조 번호 (설계)

기획서(`docs/기획서.md`)에 없는 기능이다. 기획서 5장은 등급별로 "호출 시 거부"만 정하고, 에이전트에게
무엇을 돌려줄지는 정하지 않았다.

## 1. 문제

지금까지 게이트웨이는 거부 이유를 에이전트에게 그대로 돌려줬다
(`Unknown tool`, `Tool not permitted`, `dangerous argument`, `Downstream error: <다운스트림 메시지>` 등).
에이전트 쪽에서 이 차이를 볼 수 있으면, 공격자는 도구 설명·인자를 바꿔 가며 어느 단계(이름 확인 / 판정 /
등급 / 인자 검사 / 재검증 상한)에 걸렸는지 알아내는 **오라클**로 쓸 수 있다. 응답 문구가 다르다는 것만으로도
1비트씩 새어 나간다. 보호 대상은 에이전트 LLM과 사용자 데이터이므로, 에이전트 쪽에는 아무 단서도 주지 않는다.

## 2. 결정

1. 게이트웨이가 처리하지 않고 돌려보내는 모든 `tools/call`은 원인과 상관없이 **같은 문구**를 돌려준다.

   ```
   [Linkud] 이 도구는 지금 사용할 수 없습니다. 관리자 문의 시 참조 번호: LK-XXXXXXXX
   ```

   - 대상(정책 거부): 형식이 틀린 이름, 없는 서버, 목록에 없던 도구, 판정 없음, 등급상 불허,
     위험한 인자, 재검증 상한으로 묶인 서버. "없는 도구"와 "막힌 도구"를 구분하지 않는다.
   - 대상(가용성 오류): 다운스트림 연결 실패, 다운스트림 MCP 오류, 결과 크기 초과.
     이 오류에 다른 문구를 쓰면 "정책은 통과했다"는 사실이 드러나므로 같은 문구를 쓴다.
     다운스트림이 보낸 오류 메시지(공격자가 정할 수 있는 문자열)는 에이전트에게 넘기지 않는다.
   - 대상이 아닌 것: 허용된 도구가 정상적으로 돌려준 결과(도구 자신의 `isError` 결과 포함)는 그대로 넘긴다.
2. 응답은 `isError: true`이고 내용은 위 문구 한 줄뿐이다. 등급·이유·숨긴 도구 개수·서버 이름은 넣지 않는다.
3. **참조 번호**: 거부마다 새로 만든다. `secrets.choice`로 Crockford Base32 문자(0-9, A-Z에서 I·L·O·U 제외)
   8자 = 40비트. 추측해서 남의 기록을 맞히기 어렵고, 거부 사이의 연관도 드러내지 않는다.
4. 감사 로그(`call_denied`, 가용성 오류는 `call_failed`)의 `ref` 칸에 번호를, `detail`에 원래 이유·거부 코드·
   등급·해시를 남긴다. 관리자는 `GET /admin/audit?ref=LK-...`로 그 기록을 찾는다.
5. 참조 번호는 저장소에서 **유일**해야 한다. SQLite는 `ref`에 유일 인덱스를 두고, 겹치면 새 번호로 다시
   기록한다(최대 5번, 그래도 겹치면 저장소 오류로 보고 거부 응답은 그대로 돌려준다 — fail-closed).

## 3. 거부 코드

감사 로그와 이후 기능(브레이크 글래스)이 원인을 구분할 수 있도록 내부 코드를 둔다. 에이전트에게는 보내지 않는다.

| 코드 | 원인 |
| --- | --- |
| `bad_name` | 노출 이름 형식이 틀림 (`서버__도구`가 아님) |
| `unknown_server` | 설정에 없는 서버 |
| `not_listed` | 마지막 목록에 없던 도구 |
| `no_verdict` | 판정 없음 (검증 실패·진행 중) |
| `tier` | 서버 등급상 불허 (detail에 등급) |
| `dangerous_args` | 위험한 인자 |
| `throttled` | 재검증 상한으로 묶인 서버 |
| `unavailable` · `downstream_error` · `too_large` | 가용성 오류 (`call_failed`) |

## 4. 남은 위험

- 응답 **시간**은 원인마다 다를 수 있다(예: 가용성 오류는 다운스트림을 거친 뒤 나옴). 시간 차이로 정책 통과
  여부를 짐작할 수 있다. 응답 시간을 맞추는 것은 이번 범위에 넣지 않았다.
- `tools/list`에 무엇이 보이는지는 여전히 에이전트가 안다(그 자체가 기능이다). 보이지 않는 도구의 이유는 모른다.
- 참조 번호는 비밀값이 아니다. 관리 API로만 찾을 수 있고, 번호만으로는 원인을 알 수 없다.
