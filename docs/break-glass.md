# 브레이크 글래스: 사용자 임시 허용 (설계)

기획서(`docs/기획서.md`)에 없는 기능이다. 기획서는 승인 대기 도구를 "사람이 확정"한다고만 하고, 확정 주체를
관리자로 둔다(관리 API·Slack). 이 문서는 관리자가 아닌 **사용자 본인**이 좁은 조건에서 잠시 허용하는 경로를 정한다.

## 1. 왜 필요한가

PR A(`docs/deny-response.md`)로 에이전트 쪽에는 거부 원인을 전혀 알려 주지 않는다. 오라클은 막지만, 오탐으로
정상 도구가 승인 대기에 걸리면 사용자는 매번 참조 번호를 들고 관리자에게 문의해야 한다. 이 불편을 줄이려고,
가장 좁은 경우(승인 대기 등급)에 한해 사용자가 스스로 임시 허용할 수 있게 한다.

## 2. 보호 대상과 핵심 원칙

- 보호 대상은 판별 LLM이 아니라 **에이전트 LLM과 사용자 데이터**다.
- 우회 수단이 에이전트(모델) 손에 닿으면, 툴 포이즈닝이 "이 버튼을 눌러라"라고 시킬 수 있다.
  그래서 **임시 허용은 사람만** 할 수 있어야 한다.
  - MCP 도구로 절대 노출하지 않는다(`tools/list`에 관련 도구 없음).
  - `/mcp`가 아닌 별도 HTTP 경로(`/override`)로만 받는다.
  - **에이전트가 쓰는 MCP 접속 토큰으로는 임시 허용을 받지 않는다.** MCP 토큰은 에이전트 클라이언트 설정에
    들어 있어서, 셸·HTTP 도구를 가진 에이전트가 읽어 `/override`를 직접 부를 수 있기 때문이다.
    사람 전용 토큰 `LINKUD_OVERRIDE_TOKENS`(`이름=토큰`)를 따로 두고, 이 토큰은 에이전트 설정에 넣지 않는다.
    (요구사항의 "사용자 본인 토큰"을 이렇게 해석했다. 결정이 필요한 항목 → 8장)
- 기본값은 **꺼짐**(`break_glass_enabled: false`). 꺼져 있으면 경로 자체를 등록하지 않는다.

## 3. 사용자 신원

지금까지 토큰은 사람을 구분하지 못했다. `LINKUD_AUTH_TOKENS`에 `이름=토큰` 형식을 더한다.

- `alice=0f3a...,bob=91c2...` — 이름 붙은 토큰. 인증 미들웨어가 ASGI scope의 state에 사용자 이름을 넣고,
  게이트웨이는 MCP 처리기의 HTTP 요청(`ctx.request.state`)에서 꺼내 목록 필터·호출 가드에 넘긴다.
- `0f3a...` — 이름 없는 토큰(기존 형식). 계속 동작하지만 **익명**이라 브레이크 글래스를 쓸 수 없다.
- 이름 규칙: 소문자·숫자로 시작, 소문자·숫자·`.`·`_`·`-` 64자까지. 형식이 틀리면 시작을 거부한다(fail-closed).
- 같은 이름에 토큰 여러 개(교체 중) 허용. 비밀값은 환경변수로만 받는다(운영은 SSM).
- 거부 기록(`call_denied`)의 detail에 `user`를 남긴다. 임시 허용은 이 값으로 "본인 거부"를 확인한다.
- `LINKUD_OVERRIDE_TOKENS`의 이름은 `LINKUD_AUTH_TOKENS`에 있는 이름이어야 한다(아니면 시작 거부).

## 4. 흐름

```
사용자 ──(에이전트)──▶ tools/call 거부: "… 참조 번호: LK-7H3K9QPA"
사용자 ──(브라우저)──▶ GET /override (정적 페이지)
       사람 전용 토큰 + 참조 번호 + 사유 입력 ──▶ POST /override {ref, reason}
       게이트웨이: 조건 확인 → 임시 허용 저장·감사 로그·Slack 알림 → {granted, tool, expires_at}
사용자 ──(에이전트)──▶ tools/list에 그 도구 하나만 다시 보임, tools/call 허용 (본인만, 만료 전까지)
```

## 5. 허용 조건 (전부 만족)

| 조건 | 확인 방법 |
| --- | --- |
| 기능이 켜져 있음 | `break_glass_enabled: true` (꺼져 있으면 경로 없음) |
| 사람 전용 토큰, 이름 있음 | `LINKUD_OVERRIDE_TOKENS`의 `이름=토큰`. MCP 토큰·익명 토큰은 거부 |
| 사유 | 필수, 10~500자 |
| 횟수 | 사용자별 최근 24시간 `break_glass_daily_limit`번(기본 3) 이하 |
| 본인 거부 기록 | ref로 찾은 기록이 `call_denied`이고 `detail.user`가 요청한 사용자 |
| 최근 기록 | ref가 24시간 안에 만들어진 것 (오래된 ref 재사용 방지) |
| 한 번만 | 같은 ref로 이미 임시 허용한 적이 없음 |
| 원인이 승인 대기 | `detail.code == "tier"`이고 그때 서버 등급이 `pending`. 불신·위험한 인자·없는 도구·판정 없음·재검증 상한(`throttled`)은 불가 |
| 지금도 같은 상태 | 그 도구의 현재 해시가 거부 때 해시와 같고, 서버가 지금도 `pending`(불신이 됐거나 묶였으면 불가), 그 서버의 모든 도구에 판정이 있음(검증 실패 도구가 있으면 불가) |
| 쓰기 도구 | `break_glass_allow_write: false`(기본)이면 세 신호로 읽기로 판별된 도구만 (8장) |

허용하지 않을 때는 이유와 상관없이 **"이 참조 번호로는 임시 허용할 수 없습니다."** 한 문구만 돌려준다(403).
예외로 사유 형식 오류(400)와 횟수 초과(429)는 따로 알린다. 이것은 도구가 아니라 요청한 사람에 대한 정보다.

## 6. 허용 범위와 런타임

- 범위는 **(사용자, 서버, 도구, 그 도구 해시)** 하나. 정의가 바뀌면 해시가 달라져 자동으로 맞지 않는다.
- 만료: 기본 8시간(`break_glass_ttl_hours`), 상한 24시간. 만료는 조회 시점에 판단한다.
- 그 사용자의 `tools/list`에는 그 도구 하나만 더 보인다. 다른 사용자에게는 계속 숨긴다.
- 서버가 그 사이 불신이 되거나 재검증 상한으로 묶이면 임시 허용은 적용되지 않는다.
- 호출 시 인자 검사는 그대로 한다(임시 허용이 위험한 인자를 통과시키지 않음).
- 런타임 경로(`tools/list`·`tools/call`)는 메모리 캐시만 본다. 임시 허용은 `Store`(Memory·SQLite)에 저장하고
  시작할 때 메모리로 복원한다.

## 7. 기록과 알림

- 감사 로그: `override_granted`(사용자·사유·만료 시각·ref·서버·도구·해시), `override_expired`(만료를 처음 본 때),
  `override_revoked`(관리자 회수).
- Slack이 설정돼 있으면 허용 즉시 관리자에게 알린다(사유는 기존처럼 mrkdwn 이스케이프).
- 관리 API: `GET /admin/overrides`(목록), `DELETE /admin/overrides/{id}`(회수). 정식 승인은 기존 `/admin/decisions`.

## 8. 위협과 남은 위험

| 위협 | 대응 | 남은 위험 |
| --- | --- | --- |
| 툴 포이즈닝이 에이전트에게 임시 허용을 시킴 | MCP 도구 없음, 별도 경로, MCP 토큰 거부(사람 전용 토큰) | 사람 전용 토큰이 에이전트가 읽을 수 있는 곳(같은 PC의 파일·환경변수)에 있으면 막지 못함 → 운영 문서에 보관 방법 명시 |
| 사용자를 속여 허용하게 함(사회공학: "이 번호로 허용하세요") | 승인 대기만 대상, 한 도구·한 해시·짧은 만료, 관리자 즉시 알림, 감사 로그 | 사람이 속는 것 자체는 막지 못함 |
| 남의 거부를 허용 | ref 기록의 `user`가 요청자와 같아야 함, ref는 40비트 무작위 | — |
| 허용 가능 여부를 오라클로 사용 | 거부 문구는 하나 | **허용됨/안 됨이 1비트를 준다**(그 거부가 '승인 대기' 때문이었는지). 사람 전용 토큰이 있어야 물을 수 있고, 하루 횟수 제한·감사 로그로 반복 탐색을 줄인다 |
| 허용 뒤 설명을 바꿔 악성으로(러그풀) | 해시가 바뀌면 자동 무효, 서버가 불신이 되면 적용 안 함 | — |
| 웹 페이지 XSS로 토큰 탈취 | 서버 텍스트는 `textContent`로만, CSP로 인라인 스크립트 금지, 토큰은 메모리에만(저장 안 함) | 브라우저 확장 등 페이지 밖 위협 |
| 남용(반복 허용) | 사용자별 하루 횟수, 사유 필수, 관리자 알림·회수 | 한도 안의 남용 |

**결정이 필요한 것** (구현은 fail-closed 쪽으로 했다)

1. 인증 토큰: 사람 전용 토큰(`LINKUD_OVERRIDE_TOKENS`)을 따로 둘지, MCP 토큰을 그대로 쓸지. 지금은 따로 둔다.
2. 쓰기 도구 허용: 지금은 읽기로 판별된 도구만(`break_glass_allow_write: false`). 켜면 쓰기 도구도 허용한다.
3. 하루 횟수 기준: 지금은 최근 24시간 이동 창.
