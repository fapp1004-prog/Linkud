B 전달 사항 — 2026-11-28

이번 PR은 문서의 확정된 B 독립 기능만 구현합니다.
A/C 소스, SPEC, checkers/base.py, policy.yaml, requirements.txt는 수정하지 않았습니다.
AWS 정상 307개는 원본 그대로 유지하며 업로드하지 않습니다.
수량 조정/실제 분할/최종 데이터 선정/수량 보고서는 이번 작업에서 제외했습니다.

완료한 B 독립 기능
- 기존 check(tool, server), scan(text), LLM 결과 저장 계약 유지.
- 온라인과 Batch가 공유하는 LLM 결과/예산 저장소.
- 개발 평가 동시 실행 기본 5개, 상한 5개. 결과 순서와 요청별 메타데이터 유지.
- build_dataset.py: 서버별 분리, 서버당 최대 3개, seed 42, 유사도 0.9 중복 처리.
  원본/정답 보존, 서버 정보가 없거나 라벨 충돌이면 보류, hard benign 자동 분류 없음.
  조건을 만족하고 --write를 명시해야 사본을 생성. 기본은 보고서 저장 안 함.
- 최종 Batch 준비/명시적 제출/상태 확인/수집/불확실한 제출 복구.
  고정 입력·코드·설정 검사, 회차별 custom_id, 오류/누락 분리, 검증 결과 캐시 재사용.
- 최종 Batch 완료 뒤에만 판별기 공격 시험·모델 비교를 실행하도록 입력 확인.

사용자 요청으로 반영한 위험도와 남은 논의 항목
secrecy_request(은폐 요구)만 결정안대로 60점에서 40점으로 변경했습니다.
규칙 버전은 rules-v2-secrecy40이며, 나머지 위험도/차단 기준/모델/프롬프트는 이전 PR 값입니다.
규칙 점수 (현재 / 결정안):
hidden_tag 40/40, secrecy_request 40/40, ssh_key_access 60/50,
env_file_access 50/40, tool_shadowing 60/50, invisible_chars 40/40.
현재 LLM 위험도: p < 0.5이면 0, 그 이상이면 ceil(100*p).
결정안: p 전체 구간에 대해 100*p 반올림.
남은 점수/LLM 계산 방식의 차이는 A의 최종 점수와 함께 팀이 확인할 항목이며 변경하지 않았습니다.
현재 hard_block 조합, llm_flagged 기준, confidence 의미(악성 가능성), prompt_version도 그대로입니다.
현재 모델/프롬프트가 최종 합의 완료되었다는 뜻이 아닙니다.

A와 함께 확인할 것 — 구현에서 제외
1. outputSchema/확장 메타데이터까지 변경 탐지·승인 유효성에 포함할지와 A 해시 수정.
   B는 전체 payload를 확인하지만 A가 이전 판정을 반환하면 B 호출이 없습니다.
2. 향후 B 위험도·규칙·모델·프롬프트 변경 때 A 판정/승인 무효화 방식.
3. 도구 서버 자식 프로세스에 필요한 환경변수만 넘기기.
4. B 미구현을 전제한 기존 A 테스트 기대값, Windows UTF-8 실행 환경 확인.
5. 모델·단가·팀 전체 API 예산 배분. B 로컬 DB 한도는 여러 PC의 사용량을 합산하지 못함.
6. 저장소 공개 범위 변경은 A/관리자의 결정. 이번 PR은 공개 설정을 변경하지 않음.
