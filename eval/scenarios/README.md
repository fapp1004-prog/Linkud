# 별도 시나리오 데이터 (C 작성)

설명 한 줄짜리 평가 데이터(`pure_tool.json`, eval/dataset/)와 형식이 달라서 따로 둔다.
직접 작성한 데이터라 라이선스 문제가 없어 레포에 올린다. 최종 평가 600개와 섞지 않는다.

| 종류 | 개수 | 담는 것 | 지금 시스템에서 |
|---|---|---|---|
| `rug_pull` (RP) | 8 | tools/list 1·2번째 정상 정의 → (승인) → 3번째 바뀐 정의 | A의 해시 변경 감지 + 재검사로 측정 가능 |
| `output_injection` (OI) | 7 | 정상 도구 + 호출 인자 + **실행 결과**에 숨은 지시 | 검사 범위 밖 (도구 설명만 검사) → 확장 시 측정 |
| `multi_turn` (MT) | 5 | 여러 단계에 나눠 심은 지시 | 요청 단위 검사 → 대화 기록을 보는 판별기일 때 측정 |
| 정상 대조군 (CT) | 5 | 위 세 형식과 **같은 모양**의 무해한 사례 | 오탐 측정용 |

- 모든 경로·주소·값은 가짜 (`attacker.example` 등). 실제로 읽거나 보내는 코드는 없다.
- `expected`에 기대 결과를 적어 둠: 러그풀은 `after`(바뀐 뒤 등급)와 `approval_carried: false`(이전 승인 승계 안 됨).
- RP-06은 승인된 제한 도구가 바뀌는 경우, RP-04는 스키마만, RP-07은 annotations만 바뀌는 경우.
